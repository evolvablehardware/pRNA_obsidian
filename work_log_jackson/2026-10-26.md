## Log
- Currently, the client/worker websocket communication for event handling is based on json key/value conventions. This requires keeping the server/client kv pairs consistent and a good amount of digging around to which kvs pairs are used. Cleaning this system up should make new additions easier along with communication being much more self documenting. It should also make the eventual promise like error handling system easier to implement.
	- The eventual goal is to move all of the json parameters outside of the core to dataclasses instead. Eventhandlers register on types of dataclasses rather than arbitrary event channel ids and receive the singular argument of that type of event
	- Similarly, events objects are created in the server side rather than manually building json
	- Events are translated to json in EventSender, received by EventServer, then constructed back into event objects
	- Interface:
	- ```
	  class Event: ...
	  eventsender.send(Event(), cid)
	  
	  class Handler
		  @register(Event)
		  def handle(e: Event) ...
	  ```
	  - json
	  - ```
	    [
			{
				"senders" : serial | meta -> uid
				"format": cls
				"contents": {}
			}
	    ]
	    ```
	- Keep ability to replicate a single event off of multiple targets to reduce latency
	- Include a uid for each message, unused for now but will be used in future error handling
